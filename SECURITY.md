# Segurança

O projeto está em desenvolvimento. Utilize a versão revisada pelo mantenedor e mantenha dependências atualizadas. Autenticação, permissões e configuração de hospedagem precisam ser verificadas no ambiente utilizado; testes locais não certificam um deployment remoto.

Para relatar uma vulnerabilidade, use **Security → Report a vulnerability** no GitHub quando o mantenedor habilitar relatos privados. Caso esteja indisponível, solicite um canal privado pelo [perfil do responsável](https://github.com/guiisantozs), sem publicar dados sensíveis em issues.

Inclua versão/commit afetado, impacto, condições necessárias e reprodução mínima com dados sintéticos. Não envie tokens reais, senhas ou informações de terceiros. Não faça testes de carga, alterações de produção ou acesso a contas alheias sem autorização.

Não há SLA de resposta ou suporte garantido a versões anteriores. Nenhuma credencial privada deve aparecer no cliente ou no Git. Se uma credencial vazar, revogue/substitua no provedor; apagar apenas o arquivo atual não é suficiente.
